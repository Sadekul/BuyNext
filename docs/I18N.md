# BuyNest in Bangla and English (phase 13)

The storefront speaks **English** (the default) and **Bangla (বাংলা)**. The admin stays English.
Backend side (API texts, emails, PDFs, translations of products): `docs/backend/PHASE13_CONTRACT.md`.

## How the language is chosen

1. The shopper picks **বাংলা / English** in the header (also in the footer and the mobile menu).
   The choice is saved in the cookie `buynest_lang` (1 year, `SameSite=Lax`) and, when signed in, in the
   account (`PUT /api/auth/profile { locale }` → `PATCH /api/v1/me { locale }`).
2. After sign-in the **account's** language wins. An account without one takes the language the shopper
   already chose.
3. First visit, no cookie: the store's `default_locale` (Settings → General). The browser's language never
   switches the store, but a browser that lists Bangla before English gets one dismissible "বাংলায় দেখুন" offer.
4. `<html lang>`, the page title and the default meta description follow the language. URLs don't change
   (no `/bn/` prefix; hreflang is a known limit).

Code: `src/i18n/index.js` (i18next set-up, cookie, `setLanguage`, `translate`), `src/i18n/intl.js` (numbers,
dates, digits), `src/components/layout/LanguageSwitch.jsx`, `LanguageHint.jsx`, `LanguageSync.jsx`
(store settings, account, refetching server data after a switch).

## Where the texts live

`frontend/src/locales/<en|bn>/<namespace>.json`: `common` (header, footer, navigation, UI parts, cookies,
countries), `catalog`, `cart`, `checkout`, `orders`, `account`, `auth`, `marketing` (home, newsletter, CMS
chrome), `validation` (form messages), `errors` (API, error pages), `content`. English is bundled; Bangla is
loaded on demand as its own chunk.

The sign-in service (`frontend/server/i18n.js`) has a small catalog of its own messages ("Please sign in to
continue.", "Not found.", …) and forwards the language to the API as `Accept-Language` from the cookie.
The public catalog (`/api/catalog/*`) is cached by URL, so the store adds `?lang=bn` to it instead.

## Adding or changing a text

1. Add the key to **both** `en` and `bn` files of the namespace (keys are stable ids such as
   `checkout.page.placeOrder`, never English sentences).
2. In a component: `const { t } = useTranslation('checkout')` then `t('page.placeOrder', { amount })`.
   Outside React (reducers, schemas, utils): `translate('checkout:page.placeOrder', { amount })`, called
   when the text is shown, not at import time.
3. Links or bold text inside a sentence: `<Trans t={t} i18nKey="…" components={{ signin: <Link … /> }} />`
   with `<signin>…</signin>` in both languages.
4. Counts: `_one` / `_other` keys with `{ count }`. Numbers in Bangla: write `{{count, number}}` in the
   Bangla text so the digits follow the store's "Bangla digits" setting.
5. Run `npx vitest run src/i18n` — `catalogs.test.js` fails on a missing or extra key, on a different
   `{{variable}}` or `<tag>`, on an empty Bangla value, or on a Bangla value that is still the English sentence.

## Numbers, money and dates

- Money keeps the phase 12 layout in both languages, the same as the API's emails and PDFs: symbol first,
  groups of three. Bangla with Bangla digits: **৳১,২৫০.০০**; with the setting off: **৳1,250.00**.
  (Intl's `bn-BD` currency style — `১,২৫০.০০৳`, lakh grouping — is deliberately not used.)
- Plain numbers and counts (`formatNumber`) and dates (`formatDate`) use Intl `bn-BD`
  (`bn-BD-u-nu-latn` when Bangla digits are off).
- Order numbers, emails, codes (BN-100001, NEST10) stay in Latin letters.

## Content from the API

Product names, descriptions, categories, options, specifications, CMS pages and the home hero/banners come
from the API already in the request's language, falling back to English per field. A product or page whose
text isn't translated yet is marked `lang="en"` on the page (from the API's `locale`). The Bangla-only
`short_description` shows under the product title. Labels the store wrote itself (a renamed delivery or
payment method) are shown as written; BuyNest's own defaults are translated.

## Known limits

- The `/learn` component lab (development only) stays English.
- In the DummyJSON demo the app text switches, product content stays English.
- No `/bn/` URLs or hreflang this phase.
- **Bangla in invoice and credit memo PDFs:** dompdf (the PDF engine) can't shape Bangla script. The
  PDFs use Noto Sans Bengali and the backend reorders pre-base vowel signs (ি, ে, ৈ) so they draw in
  the right place, but conjuncts show a visible hasanta (for example ন্ট, র্ড instead of the joined
  letter). The text is readable; a fully shaped PDF would need a different engine (for example a
  headless browser) in a later phase. The emails and web pages are not affected.
- Quantity boxes (`<input type="number">`) show Latin digits even in Bangla: browsers only accept
  Latin digits in number fields.
- Messages typed by staff (product names, home banners, a free-shipping amount typed into the home
  hero) are shown as written: add their Bangla versions in the admin.
