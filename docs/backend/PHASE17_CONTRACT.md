# Phase 17 contract: marketplace-style storefront (Fastkart-like layout)

**Status: built (2026-11-25).** Asked by the store owner: "I need this type of frontend design" (Pixelstrap's Fastkart template, themes.pixelstrap.com/fastkart/front-end/index-9.html), then "start work; carefully don't miss any functionality or bugs". Fastkart is a **commercial ThemeForest template**: we build an **original** design in the same style (dense marketplace layout, the same kinds of sections and conveniences). **Never copy its code, CSS, images, icons, fonts files, or text.** The indigo + coral theme from the redesign stays (tokens in `frontend/src/assets/styles/tokens.css`; colours are a one-file change later).

Keeps every convention (phases 1–16, `docs/STOREFRONT_REDESIGN.md`): English + Bangla for all shopper text (Bangla digits), phones first (no sideways scroll at 390px), WCAG 2.1 AA (contrast, keyboard, focus, reduced motion), the DummyJSON demo mode, existing accessible names used by tests, `snake_case` API / camelCase BFF, 422 by path, audit on admin saves. **No fake data or urgency**: no invented "sold in the last N hours", no countdown without a real end date, coupons only when real and active, "best selling" only from real orders.

## 1. Backend (Laravel)

1. **Best selling:** `GET /api/v1/products?sort=best_selling` — ordered by units sold in orders that are not cancelled (`order_items.quantity`, last 90 days; ties by rating, then id). Also usable with `category`. Admin list may accept it too.
2. **Delivery estimate:** `GET /api/v1/delivery/estimate?area_id=` (public, throttled, cacheable by area and language) → `{ data: { area: {id, name, district, division}, zone: {code, name} , methods: [{id, label, price, eta, eta_days_min, eta_days_max, free_over_threshold}], free_shipping_threshold, cod: {available, reason|null, fee} } }`, computed with the same services as checkout (`ShippingRates::options` with the area's zone, an empty cart: 0 g, subtotal 0; COD rules from `CashOnDelivery`). 422 `area_id` for unknown areas. Only meaningful when the store's default country is Bangladesh; otherwise 422 `area_id` "Delivery areas are for Bangladesh addresses."
3. **Top promo strip** (admin-editable, part of the home content so it saves with the home page): `top_bar: { enabled: bool, message ≤120, message_bn ≤120|null, coupon_code: string|null }` in `GET/PUT /api/admin/v1/home` (kept when left out, like the slider keys). Public `GET /api/v1/home` → `top_bar: { message (in the request language, English fallback), coupon_code|null }` or `null` when disabled/empty; `coupon_code` only when it is an existing, active, currently valid coupon (else null). 422 `top_bar.coupon_code` "This coupon doesn't exist or isn't active." on save when the code isn't an active coupon.
4. Tests for each; everything else keeps passing.

### Implementation notes — backend (§1)

**Best selling** — `GET /api/v1/products?sort=best_selling[&direction=asc|desc]` (default `desc`).
- Units = `SUM(order_items.quantity)` of orders with `status != 'cancelled'` and `orders.created_at >= now - 90 days` (`Product::BEST_SELLING_DAYS`); products never sold (or only outside the window) count 0. Ties: `rating_average` desc, then `products.id` asc (so pages never overlap). `direction` flips only the units order.
- SQL: `Product::orderByBestSelling()` (scope in `app/Models/Product.php`) left-joins one grouped subquery (`best_sellers`) and selects `products.*`; no per-product queries, the extra columns never reach the resource. Works with every other filter (`category` incl. subcategories, `brand[]`, prices, rating, `available`, `search` — with `sort` given, search filters but doesn't rank) and with pagination (`meta.total` unchanged).
- New indexes (migration `2026_11_25_000100_add_best_selling_indexes`): `orders(created_at, status)`, `order_items(order_id, product_id, quantity)`.
- **`units_sold` / `meta.has_sales`** (only when `sort=best_selling`): each list item gets `"units_sold": 7` (integer, the exact number the sort uses: last 90 days, not cancelled, 0 when never sold), read from the joined subquery's column (no extra per-product work). The response gets `"meta": { …pagination…, "has_sales": true }` — true when **any** product of the whole filtered result (all pages, same filters) has `units_sold > 0`; `false` means the order is really the rating order, so the storefront shouldn't call it "Best selling" (e.g. hide that tab or fall back to "Top rated"). One extra `EXISTS` query on the same joined subquery. With a search, `has_sales` sits next to `redirect_url` / `corrected_query`. Every other listing (other sorts, no sort, product detail, home, compare) has neither key.
- The admin product list was **not** changed (optional in §1).
- An unknown sort is still 422 `sort` ("The selected sort is invalid.").

**Delivery estimate** — `GET /api/v1/delivery/estimate?area_id=` (public, `throttle:api` like the places, `Cache-Control: public, max-age=600`, `Vary: Accept-Language`; not cached on the server — 10 minutes rather than the places' day because charges and COD rules are admin-editable).

```json
{ "data": {
  "area": { "id": 1203, "name": "Dhanmondi", "district": "Dhaka", "district_id": 47, "division": "Dhaka", "division_id": 6 },
  "zone": { "code": "inside_dhaka", "name": "Inside Dhaka" },
  "methods": [
    { "id": "standard", "label": "Standard", "price": "60.00", "eta": "Delivery in 1–2 days", "eta_days_min": 1, "eta_days_max": 2, "free_over_threshold": true },
    { "id": "express", "label": "Express", "price": "12.99", "eta": "1–2 business days", "eta_days_min": null, "eta_days_max": null, "free_over_threshold": false }
  ],
  "free_shipping_threshold": "50.00",
  "cod": { "available": true, "reason": null, "message": null, "fee": "20.00" }
} }
```
- Names (`area.name`, `district`, `division`, `zone.name`), method `label` and `eta` are in the request language (Bangla: bn names, "২–৩ দিনে ডেলিভারি" with the digits setting). Additive to §1: `area.district_id`, `area.division_id` (for the checkout prefill) and `cod.message` (the shopper-facing sentence).
- Computed like checkout: `DeliveryZones::zoneFor(area, district)` → `ShippingRates::options(Settings::shippingMethods(), "Bangladesh", 0 g, subtotal 0, zone)`. Methods whose table rows match nothing are left out; methods without rows keep their flat price and ETA text. `price` is the method's price for an empty cart (the free-shipping threshold is **not** applied; the storefront shows `free_shipping_threshold` next to methods with `free_over_threshold: true`). `zone` is `null` when no active zone (and no active fallback) covers the area.
- `cod`: `reason` is `null` | `"zone"` ("Cash on delivery isn't available in your area.") | `"disabled"` (COD isn't an enabled payment method: "Cash on delivery isn't offered right now."). The order-total limit can't apply to an empty cart, so `"limit"` never appears here (checkout still checks it). `fee` = Settings → COD fee.
- 422 (all on `area_id`):
  - missing / not a positive integer / unknown area: "Choose your area (upazila or thana)." (bn: "আপনার এলাকা (উপজেলা বা থানা) বেছে নিন।")
  - store `default_country` isn't Bangladesh ("Bangladesh" or "BD"): "Delivery areas are for Bangladesh addresses." (bn: "ডেলিভারি এলাকা শুধু বাংলাদেশের ঠিকানার জন্য।") — checked before the area lookup.

**Top promo strip** — `top_bar` in the home content.
- Admin `GET /api/admin/v1/home` and the `PUT` response: `"top_bar": { "enabled": false, "message": null, "message_bn": null, "coupon_code": null }` (this default for content saved before phase 17).
- `PUT` takes `top_bar: { enabled?, message?, message_bn?, coupon_code? }` (no other keys). Normalized: texts trimmed (empty → `null`), `coupon_code` upper-cased (empty → `null`). **Left out of the PUT → the stored strip is kept** (as `hero_mode`/`slides`/`slider`); `top_bar: null` sent explicitly resets it to the default (hidden).
- 422 messages (admin, English):
  - `top_bar.message`: "Write the promo message, or turn the promo strip off." (enabled without a message); "The promo message has at most 120 characters."
  - `top_bar.message_bn`: "The Bangla promo message has at most 120 characters."
  - `top_bar.coupon_code`: "This coupon doesn't exist or isn't active." — only for a **new or changed** code (compared with the stored one trimmed, case-insensitive): unknown code, an automatic rule, or `Coupon::status()` other than `active` (switched off, scheduled, expired, used up); also for a code over 40 characters.
  - `top_bar`: Laravel's standard `array` rule message for unknown keys or a non-object.
  - An **unchanged** stored code is accepted even when it is no longer active (the admin always sends `top_bar` back, so an expired coupon must not block e.g. a banner edit); the public `/home` hides it while inactive. The same holds when `top_bar` is left out and the stored strip is merged in. Clearing the code and later typing the expired one again counts as new (422).
- Audit: part of the home save (`home.updated`, summary lists `top_bar` among the changed keys, before/after in `changes`).
- Public `GET /api/v1/home` → `"top_bar": { "message": "Eid sale: 10% off", "coupon_code": "EID10" }` or `null` (disabled or no message). `message` = `message_bn` for Bangla requests when filled, else English. `coupon_code` = the stored code only while it is an existing, non-automatic coupon with status `active` (checked on every request), else `null` — the strip stays with its message.

**What the browser suites may notice**
- `page.getByRole('combobox').first()` (storefront.mjs, extras.mjs, marketing.mjs) is still the search box **unless the store offers a display currency**: the currency select is now in the top bar, before the search in the DOM. loyalty.mjs turns BDT on; if a later suite runs with it still on, use `getByRole('combobox', { name: 'Search products' }).first()`.
- `getByRole('button', { name: 'Search' })` at 390px now also matches the tab bar's "Search" button (hidden from 768px).
- The announcement bar's markup (`.announcement-bar`) is gone; the top bar is `.top-bar` inside `.site-header` (so `.site-header` innerText now includes the delivery line, the promo and the currency codes).
